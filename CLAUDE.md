# EduSphere

## If you are new here, read in this order
1. `CLAUDE.md` (this file): the rules and the layout.
2. `docs/VISION.md`: why the product exists and how to judge a change.
3. `README.md`: what it does, for a person.
4. `docs/ALGORITHMS.md`: every number, in plain terms, with its reason.
5. `docs/DECISIONS.md`: what was decided, when, and why. Do not reopen these without reading.
6. `docs/DESIGN.md`: how screens look and how words are written.
7. `src/curriculum.mjs`: the plan against state standards, and what is still missing.
8. `docs/RUNBOOK.md`: what to do when something breaks.
Then `src/logic.mjs`, then `src/ui.jsx`, then the tests. Run `./check.sh` before and after any change.

Mastery-based learning for schools. Phase 0 = one browser file, no server, no
accounts, no data leaves the device. Decisions and the phase 1 plan live in
docs/DECISIONS.md. What to do when something breaks lives in docs/RUNBOOK.md. Step-by-step guides live in .claude/skills/.

## Commands
- `./check.sh` — runs everything (rules tests, curriculum coverage, build, render smoke, syntax, browser click-through). Must end with `ALL CHECKS PASSED`. Run after every change and paste the last line.
- `node tests/logic.test.mjs` — rules only; fastest loop while changing logic.
- `tsc` prints one line `Cannot find module 'react'` — ignore that line only.
- `./check.sh` step 5 is a real-browser click-through (`tests/e2e/click-through.mjs`, headless Chromium, about a minute). If only step 5 fails, read its FAIL line: it names the screen and the tap.

## Layout
- `src/logic.mjs` — content, question generators, mastery rules, event-log derivations, reports. No screens.
- `src/ui.jsx` — screens only. No rules.
- `index.html` — the standalone product for GitHub Pages and any web host, generated by `tools/build-site.mjs` (React bundled in, storage on localStorage). Never edit it by hand. `.nojekyll` keeps GitHub Pages from processing the repository.
- `src/curriculum.mjs` — the plan: every published standard per grade and subject, and which modules cover it. `tests/coverage.test.mjs` reports gaps and fails for any grade marked `ready` with a standard uncovered. Never mark a grade ready to make it pass.
- `build.sh` → `dist/edusphere-prototype.jsx` (generated; never edit by hand).
- `tests/logic.test.mjs` — the rulebook, executable. `tests/render.smoke.test.mjs` — the built file renders.
- `tests/e2e/` — `make-page.mjs` builds a browser page from the real artifact; `click-through.mjs` taps through every screen.

## Rules that must stay true (the tests enforce most of these)
1. The event log is the single source of truth; mastery, status, and every report number are computed from events. Nothing stores "mastered = true".
2. Events are only added, never edited or deleted. A reset is an event; derivations ignore events before the latest reset. `courses_enabled` settings survive a reset.
3. A module opens only when every prerequisite is mastered: the module before it in its course plus anything in its `requires` list, which may cross courses and grades. `checkPrerequisiteGraph` must return no problems; a cycle would lock a student out forever.
4. Review questions never affect the mastery gate.
5. Every answer and explanation is computed by arithmetic, never written by an AI. Each generator is re-checked with 300 seeds by an independent test.
6. Every module has at least 5 question types.
7. Sources are plain text, never links. No links on learner screens.
8. A question is a `story` line (may be null) plus a one-sentence `prompt` under 70 characters.
9. Learner screens use plain words and no raw statistics. The educator view holds definitions, raw log, reset, course switches.

## Gotchas
- In `ui.jsx`, all hooks (`useState/useEffect/useMemo`) stay above the first `if (screen === ...) return`. A hook below a return crashes with "Rendered more hooks".
- The artifact host blocks `localStorage`/`sessionStorage`, `<form>`, and external scripts. Storage is rate-limited: use `storageGet/storageSet/saveRecord` only; do not add new storage calls.
- Picture choices are strings like `dots:4`; the screen draws them. `describeChoice()` turns them into words.
- The quick check ("I already know this") is a normal practice round with `attempt.quickCheck` and no lesson; `buildQuickCheck`, `quickCheckAllowed`, `makeQuickCheckEvent` and `makeQuickPlacedEvent` live beside placement in `logic.mjs`, and a pass is a `placed` event with `quickCheck: true`.
- In the browser test, `window.__eduTest.openModule(id)` opens a named module from any overview; the test page has `hasTouch: true` so tracing lessons open. Every pass ships the full zip, a changes-only zip (files that differ from the last delivered zip, for drag and drop, with CHANGES.md inside as the commit message), and a hosted preview: run `tools/changes-zip.sh <previous-project.zip> /mnt/user-data/outputs` after check.sh, then publish index.html with the Artifact tool (a .jsx file only downloads on a phone; the published page opens).
- Lesson pictures are drawn by `Picture` in `ui.jsx` by `kind`. Kind `trace` draws a `TRACE_LETTERS` shape drawing itself (`TraceDemo`); every touch lesson's script uses it, and `tests/scripts.test.mjs` fails if one does not.
- Number answers are whole numbers as strings; `checkAnswer` is the only place answers are compared.
- Courses with `readAloud: true` speak questions; their answers must be tappable, never typed.
- `window.__eduTest` in `ui.jsx` is a read-only hook the browser test uses to see the current screen and question. Leave it in place.
- Logo: `Logo` in `ui.jsx` draws geometry from section 6 of `logic.mjs` (`layoutWord`, `buildSphereArcs`, `buildSphereFlecks`, `buildAccentArc`, `WORDMARK_GLYPHS`). Change numbers there, never hand-edit paths, and re-export `docs/logo.svg`. Full spec in docs/DESIGN.md.
- Optional sections are switched by `FEATURES` in `logic.mjs`: `reflection` (Wonder + Wisdom), `lifeSkills`, `checks`. Turning one off must remove it from every screen — nothing else may depend on it. This is how the platform is stripped down for trade/corporate training.
- Courses are organized grade-first: every course has a `grade` from `GRADES` ('K' through '12'). Screens pick a grade, then a subject, then a course. Helpers: `gradesWithCourses`, `subjectsForGrade`, `gradeLabel`.
- Mastery numbers are per module, not global. Read them with `moduleRules(moduleId)`, which falls back to the course setting and then to CONFIG. Never assume five questions.
- Collapsed sections on the educator report are rendered but hidden with `display: none` and the class `edu-collapsible`, so printing shows everything. Do not switch them back to conditional rendering. Anything that should not print carries `edu-no-print`.
- Life skills (section 8 of `logic.mjs`) are suggestions for educators, never shown to students and never tracked. They are an ordered sequence from earliest to most mature, NOT assigned to grades: a mixed age classroom has no single grade to look under, and nobody can honestly place a skill in one year rather than the next. Order in the array is the maturity; `lifeSkillsInOrder` adds position and a 0 to 1 maturity value that the screen turns into a colour. `LIFE_STAGES` marks four bands down the column (early, growing, teen, grown) and every skill names one. Marking a skill covered is the classroom's own bookmark and is NEVER attached to a student, which is what keeps this section outside the student record.
- WARNING: never run a blanket find-and-replace on an element that also appears inside the component that renders it. Swapping the frame div for `<PageChrome />` once hit PageChrome's own body and made it render itself forever, which hung the browser with no error message. The smoke test now fails if the first screen exceeds 60,000 characters.
- WARNING: the word `grade:` appears in both COURSES and other data. Never bulk-remove or rewrite it with a blanket search: doing so once stripped the grade from every course and broke the whole report.
- The transcript (`buildTranscript`) keeps courses that are no longer assigned, leaves out courses never opened, and carries nothing a student wrote.
- IMPORTANT: user-facing text varies sentence length, stays very simple, uses complete sentences, and never uses an em dash. Full rule and vocabulary in docs/DESIGN.md.
- `summaryParagraph(report)` describes every assigned course at once and takes no grade. `courseLabel`, `gradeShort` and `gradeInSentence` in `logic.mjs` give the standard wording for a course anywhere it appears.
- The recommended course list on the educator report is worked out once when the report opens (`recommendedIds` state). Never recompute it on every change: the rows would shift under the educator's finger.
- Educator screens are grade-first: a grade picker at the top, then the plain-English summary, an 'Assigned now' flat list across all grades, subject/course checkboxes for the chosen grade, and per-subject progress panels. `EXPLANATIONS` in `logic.mjs` holds the plain-language definitions shown on the report — edit them there, not in the screen code.
- Starting levels (`LEVELS`) are where placement begins, never a verdict. A student's `level` narrows recommendations to its band; a band with no courses recommends nothing rather than falling back to kindergarten.
- Student pictures (`PICTURES`) are drawn in the app and chosen from a fixed set. Never add photo upload: a photo of a child is personal information under COPPA, and eight drawn animals do the same job with nothing to protect.
- A module that needs a finger on glass sets `needsTouch: true`; `courseNeedsTouch` shows the educator a warning before assigning.
- Roster (section 7 of `logic.mjs`): admins create student IDs; students pick from the list and never type one. Roster helpers return a NEW roster and never edit in place. `normalizeStudentId` makes the storage key; the readable `label` can change but the `id` never does, so progress cannot be stranded.
- Two kinds of reset, both append-only: `makeResetEvent` clears everything, `makeModuleResetEvent` clears one module. Neither deletes history.
- `summaryParagraph` builds the educator's plain-English paragraph from the report, so it can never disagree with the numbers beside it.
- Loop-back routing: after `LOOP_BACK_AFTER` (2) failed rounds in a row, `loopBackTarget` names the prerequisite to revisit, and `makeLoopBackEvent` records that it happened. Re-passing the prerequisite clears it. Loop backs are events like everything else; they never delete or alter mastery.
- Local-first (section 9 of `logic.mjs`): `buildBackup`, `checkBackup`, `mergeBackup`. Restore never overwrites and never deletes; it merges by student id and joins event logs. Any change here must keep the test 'restoring an old backup never loses newer work' passing.
- Words for people live in `logic.mjs`: `moduleStory` (the educator's conversational account of one module) and `encouragementFor` (what a learner is told when a round ends). Screens call these; they never assemble sentences from numbers themselves.
- Pre-reader courses (`isPreReader`) must work without words: spoken lessons driven by `lesson.script` (example first, then the rule), symbols instead of status labels, tapping instead of typing, and retry until correct. In those courses a result's `correct` means right FIRST time, so mastery still measures knowledge rather than persistence.
- Reflection questions are opt in: nothing reaches a student until somebody at the school approves it. `wonderFor(courseId, seed, review)` returns null for anything unapproved, so a missing review state means no reflection content at all. That default is deliberate and must not be flipped.
- Wonder screens never save a child's words (compliance). `makeWonderEvent` stores only id, time, seconds, word count.
- Pre-K rule (2026-09-20): while any pre-K module is unmastered the overview groups by skill (`youngGroups` in `ui.jsx`) and holds kindergarten courses out of sight, even when `coursesToUnlock` has switched one on. Do not let the pre-K screen change shape before the last pre-K module is mastered.
- Back button (2026-09-20): one guard entry on `window.history` while the app is past the sign-in screen; `popstate` moves up one level (`upScreen` in `ui.jsx`). Never push more than one entry, and never navigate on `popstate` from the sign-in screen.
- Speech (2026-09-20): `speak()` is ticketed; never call `speechSynthesis.speak()` straight after `cancel()` anywhere else. Keep utterances referenced (`speechAlive`).
- Student PIN and Wonder switch (2026-09-20): `cleanPin`, `setStudentPin`, `pinMatches`, `setStudentWonder`, `wonderOnFor` in section 7 of `logic.mjs`; the sign-in screen asks for a PIN when the student has one; both result screens check `wonderOnFor`. Classroom order: `classroomOrder` and `setClassroomOrder`.
- Backups (2026-09-20): `autoBackup(reason)` runs on sign-out, first sign-in of the day and course finish; `keepOneFile` holds a file handle in memory only. Do not add a storage call for the handle.

## Workflow
- One-sentence change (wording, a color, a typo): do it, run `./check.sh`, show the output.
- Anything larger: say which files and which rules above it touches, then implement, then `./check.sh`, then a fresh-context review (`.claude/agents/reviewer.md`).
- IMPORTANT: no AI-written facts in content. Answers are computed or come through the phase 2 verification pipeline (docs/DECISIONS.md).
- IMPORTANT: existing lines in this file are not changed without Mikey's approval. Adding lines is fine.

## Compliance (drives every decision)
Schools are the only customers. Identifier = school-issued ID. No names, emails, photos, voice, or free text from children. No trackers. Read-aloud is output only. Full rules in docs/DECISIONS.md.

## Which model for which job
- Strong model: rules 1–4, anything security/privacy/compliance, new reports or derivations, reviews of larger changes.
- Cheaper model: wording, lessons, new question types and courses via the skills, styling, small bug fixes — always finishing with `./check.sh`.

## Vision (why every rule above exists)
- Goal: every student masters their grade's standards in a fraction of the school day, and the freed time goes to life skills. Efficiency is measured in minutes per day and learning gains, never assumed.
- Mastery is proven (4 of 5, retention checked later), tracked by a confidence score whose rules are printed on the report.
- Reports are trusted because they are recomputed from an unchangeable record with definitions shown.
- Learning should feel good: short questions, pictures, spoken words for young children, Wonder questions with no right answer, no pressure tricks.
- Schools are the customer; privacy is designed in, not added.
- Design and layout rules: `docs/DESIGN.md`. Session start prompt: `docs/DESIGN.md` bottom.
